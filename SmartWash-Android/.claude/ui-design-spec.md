## 0. 背景：上一版为什么被判"简陋"

上一版遵循"不用阴影、靠底色差造层次、极简白卡"，方向没错，但几个具体取值叠出了"简陋"而不是"简约大气"：

| 问题 | 事实 |
|---|---|
| 底与卡片分不开 | 底 `#FAFAF8` vs 卡 `#FFFFFF`，对比只有 **1.04:1**，卡片看不见，页面糊成一片 |
| 卡片有三种画法 | 无边框 / 0.5dp 描边 / 灰底，同一 App 三种物件感 |
| 图标是"图标字体" | 104 处 Material Icons，**变体混用**（Filled + Rounded + Outlined），且多为裸图标无容器 |
| 零图像语言 | 全项目 `painterResource` 0 处，无插画，Canvas 只有观象台 3 处 |
| 排版只有两级 | 最大 32sp 只给页面标题，金额/余额/取件码与正文同量级 |
| 品牌色缺席 | `#2D9B6A` 只出现在按钮与价格，约 95% 面积是灰白 |

**核心认知**：简约是删掉不必要的；简陋是缺少必要的。苹果式极简成立的前提是极简表面之下有大量工艺**和大量图像**。只留白盒子，就是简陋。

## 1. 设计原则（五条，可判定）

1. **把"洗衣"当素材，不是当背景。** 水、泡沫、织物、滚筒、晾晒、打孔洗衣票、寄存柜——这些物质必须出现在界面里。判断标准：一个新用户扫一眼，应该看出这是洗衣产品而不是通用工具。
2. **每屏一个视觉锚点。** 每页最多一个"重"元素（hero / 大图 / 大数字 / 滚筒），其余全部安静。锚点超过一个就是没有锚点。
3. **层次靠底色、边界、留白三件套，不靠分割线。** 0.5dp 发丝线只能用在**同一容器内部**的行之间，不能用来切分页面区块。
4. **品牌色是氛围，不是按钮色。** 绿色必须出现在：hero 渐变、区块标题装饰、选中态底、图标容器、数据强调——至少三处非功能位置。
5. **稀疏比拥挤大气。** 宁可一屏少放一个模块，不要压缩间距。间距是本设计系统里最便宜的"高级感"。

### 2.4 层级

| 层 | 规格 |
|---|---|
| 卡片 | 1px `#E3E7E2` 描边 + `0 2px 12px rgba(20,40,30,.05)` |
| 浮层 / 弹窗 | `0 10px 24px rgba(20,40,30,.10)` |

## 3. 组件规范

### 3.1 卡片（唯一画法）

```
形状   16dp 圆角
底     纯白 #FFFFFF
描边   1px #E3E7E2
阴影   0 2px 12px rgba(20,40,30,.05)
内边距 20dp
```

**禁止**：❌ 灰底卡片（旧 `surfaceVariant` 卡片）❌ 无描边无阴影的裸白卡 ❌ 0.5dp 描边卡片。三者必须统一成上面这一种。

**卡片变体**：
- **Hero 卡** — 品牌渐变底 + 白字 + 白色 CTA 胶囊。每页至多 1 个。
- **信息卡** — 上述标准卡片。
- **票券卡** — 白卡 + 左右半圆打孔 + 中间虚线。用于优惠券、取件票。

### 3.2 图标容器

**所有功能图标必须放进容器，禁止裸图标直接着色。**

| 尺寸 | 容器 | 圆角 | 图标 | 线宽 |
|---|---|---|---|---|
| 主 | 44dp | 12dp | 22dp | 2px |
| 次 | 36dp | 10dp | 18dp | 2px |
| 小 | 32dp | 10dp | 16dp | 1.8px |

容器底色从**六色浅底**里按语义取，图标用对应的深色版（如绿底用 `#2D9B6A`）。
语义对照：充值/校园卡/安全类→**青**，观象台及其子功能→**紫**，通知/提醒/待办→**橙**，异常/取消→**粉**，物流/寄件/订单查询→**蓝**，洗护主流程→**绿**。

**豁免**：导航返回箭头、表单输入前缀图标可不入容器（平台惯例），但必须保证 48dp 触控热区。

### 3.3 按钮

| 类型 | 规格 |
|---|---|
| 主按钮 | 高 52dp，圆角 14dp，品牌渐变底，白字 15sp/600，letterSpacing 1sp |
| 次按钮 | 高 52dp，圆角 14dp，`#F5F6F3` 底，主文本色 |
| 文字按钮 | 主色 13sp/600，无底无框 |
| 小按钮 | 高 36dp，圆角 12dp，横向内边距 16dp |

按压反馈：**scale 0.97 + 100ms**（见 §7）。

### 3.4 列表行

高 56dp，左图标容器（36dp）+ 主文案 14sp/500 + 副文案 11sp/次文本 + 右侧值/箭头。
行间分隔用 **0.5dp `#EFF1EE`**，且**只在同一张卡片内部**使用。

### 3.5 状态色点

8dp 圆点，位于卡片左缘外或行首：进行中 `#D98A26` / 已完成 `#2D9B6A` / 完成 `#34C759` / 异常 `#C9526B`。

### 3.6 空态 / 加载 / 错误

| 状态 | 规范 |
|---|---|
| 加载 | **骨架屏**（形状与真实内容一致，微光扫过）。禁止用居中转圈占位列表。 |
| 空态 | 滚筒圆母题（见 §5）静止态 + 一句引导文案 + 一个行动按钮。**禁止**用一个灰色 Material 图标了事。 |
| 错误 | 说明**发生了什么**+**怎么解决**，不道歉、不含糊。给重试按钮。 |

## 4. 图标体系

### 4.1 范围与来源（**已定案，不要再讨论**）

**全项目自绘仅限下表所列（tab 8 + 动效 4 + 品牌图标 2），其余一律继续用 Material 内置。**

| 范围 | 数量 | 来源 | 状态 |
|---|---|---|---|
| **底部 tab 图标** | 4 图标 × 线性/实心 = **8 个** | **自绘**（本项目自有） | 路径已定稿，见 §4.5 |
| **动效图标**（滚筒 / 水滴 / 水波 / 泡沫） | **4 个** | **自绘 + Compose Canvas** | 路径与动效已定稿，**全文见 §4.5 附** |
| **认证页品牌图标**（洗衣机） | **1 个** | **自绘** | 登录页品牌标识（基线⑩）；ic_washing_machine.xml（ed7e76c） |
| **注册页品牌图标**（水滴+加号） | **1 个** | **自绘** | 来源：设计稿屏 2（替代 emoji），2026-10-06 补录；ic_water_add.xml |
| **其余全部功能图标** | 104 处 `Icons.*` | **保持 Material 内置，不替换** | **不动** |

**为什么不做全量替换**：Material 图标本身合规、齐全、零维护成本；自绘 104 个的收益远低于成本。
只有三类必须自绘——**tab 图标**（Material 没有"线性/实心成对 + 可动效"的组合）、**动效图标**（要跑 Canvas 动画）、**品牌标识**（设计稿定稿造型）。

❌ **不要再提议**：引入 Lucide / Tabler / Phosphor / Iconoir / Remix / IconPark 等外部图标库。
调研过，结论见 [docs/design/图标库调研.md](docs/design/图标库调研.md)：Lucide 无填充版、Iconoir 的 solid 是精选子集、
**iconfont 授权不统一不可商用**、**SF Symbols 许可只允许 Apple 平台**、Remix Icon 已从 Apache-2.0 改为自订协议。

**许可证要求**：自绘件为本项目自有，无需外部核验。**若将来确需引入外部图标**，必须
① 拉到官方仓库 `LICENSE` 原文确认；② 记录来源 URL / 版本或 commit / 许可证 / 引入日期。
**凭印象写许可证名 = 返工。**

### 4.2 造型规范（图标"丑不丑"取决于这一节）

> 本节规则来自对 **TDesign Icons（MIT）** 源码的实测 + **Material / Apple / Ant Design / Lucide** 官方规范的对照，不是自拟。
> 调研全文见 [docs/design/图标库调研.md](docs/design/图标库调研.md)。
>
> 血泪教训：手写路径必然出问题——屋顶 38°、箱体斜边 7°、圆角忽大忽小、**四个图标视觉尺寸是 20.9×21.2 / 17.4×21.2 / 21.2×19.6 / 21.0×20.5**。
> 单个看都没事，并排就明显不齐。

**① 关键线：线性版 18×18，实心版 20×20**

画布 24×24。**关键线不是一个尺寸，两版不同**——这是最容易搞错、也最要命的一条：

| | 路径范围 | 视觉范围 | 说明 |
|---|---|---|---|
| **线性版** | **3–21（18×18）** | 2–22（20×20） | 2px 描边自己会向两侧各占 1 |
| **实心版** | **2–22（20×20）** | 2–22（20×20） | 没有描边，路径必须自己画到边界 |

⚠️ **实心版必须比线性版向外扩 1。** 两版用同一套坐标 = 实心版永远小一圈、虚一圈。
（Material 官方口径：live area 20×20，关键线正方形 18×18。TDesign 的 `home` 路径正好 3–21。）

关键线形状（同组内必须贴合其中一条）：

| 形状 | 线性版 | 实心版 |
|---|---|---|
| 正方形 | 18×18 | 20×20 |
| 圆形 | ⌀18 | ⌀20 |
| 竖矩形 | 14×18 | 16×20 |
| 横矩形 | 18×14 | 20×16 |

**② 圆角：两个流派，选定一个，别混**

| | 硬朗派 | 圆润派 |
|---|---|---|
| 端点 / 连接 | `square` + `miter` | **`round`** |
| 转角 | 直角 | 外 R1.5–2 |
| 代表 | TDesign、Ant Design | **Apple SF Symbols**、Material、Lucide |

**本项目采用圆润派（Apple SF Symbols）**：`strokeLineCap` / `strokeLineJoin` 一律 `round`，
实心版转角 R1.5–2，细条（高 2 的镂空）R1。

**③ 角度：整组统一，不是死磕 45°**

不要求全是 45°。要求的是**同一组内一致**——TDesign 的屋顶是 39.8°，Lucide 的斜线是各种角度，
各自的组内是齐的。真正的错是"屋顶 38°、箱体斜边 7°"这种随手写的值。

**④ 镂空宽度 = 描边宽度 = 2**

实心图标的视觉重量由**镂空宽度**决定，不由轮廓决定。

- 镂空宽度统一 **2**（与描边宽度相同）
- 同一组内门窗、条纹、搭扣全用这一个值
- 26dp 显示时镂空不得小于 2，否则糊成一团

**⑤ 描边不得覆盖镂空**（踩过的坑）

描边是**沿路径居中**描的：`stroke-width 2.2` → 每侧各占 1.1。
如果描边路径包含了镂空子路径，一条 2 高的缝会被 2.2 的描边**完全填死**——
缝先消失、等填充用 `evenOdd` 进来才重新出现，视觉上就是"镂空被挤掉又冒出来"。

**正确做法**：描边**只画外轮廓**，镂空**只由填充层用 `fillType="evenOdd"` 表达**。
动画时也要保证前后两层用**同一条带镂空的路径**交叉淡变，镂空才不会中途消失。

**⑥ 细节密度一致**

一组内每个图标的镂空数量差 **不超过 1**。26dp 下宁可少一个细节，也不要塞——小尺寸糊掉比少个细节更丑。

**⑦ 自检：必须跑几何校验，不能靠眼睛**

写完路径用脚本验四条，任一不过就返工：

1. 包围盒落在关键线内（线性 3–21 / 实心 2–22），容差 ±0.15
2. 视觉尺寸 = 关键线 + 2（线性）或 = 关键线（实心），**一组内每个图标必须相等**
3. 左右对称：`|(x_min − 12) + (x_max − 12)| < 0.1`
4. 斜线角度在同一组内一致

⚠️ **校验器本身也要验。** 本次踩过：解析器把数字 token 当成命令字母，
静默丢掉 SVG 的隐式参数（`M3 9.5 12 2.5` 里的 `12 2.5`），然后给出一句"全部通过"——
四个越界的图标被放行了整整三轮。

### 4.3 命名与目录

```
res/drawable/
  ic_nav_<名称>.xml        底部 tab 图标（8 个）
  ic_<名称>.xml            动效图标（4 个）
```

加载一律 `painterResource(R.drawable.xxx)`。

**SVG / Figma 导出转 VectorDrawable 的四个坑**（每个都踩过或已知）：

1. **颜色会被写成硬编码** → 一律改成 `android:strokeColor="#FF000000"` 纯黑或直接删掉，
   **着色交给 Compose 侧 `Icon(tint = ...)`**，否则双主题换不了色
2. **`stroke="currentColor"` 不会被识别** → 必须显式落到 `android:strokeColor` + `android:strokeWidth`
3. **VectorDrawable 不支持 `<mask>` / `<filter>` / 复杂渐变** → 手工降级，或放弃该图标
4. **文件名里别有空格或中文**；路径坐标必须落在 `viewportWidth/Height = 24` 内

> ⚠️ **编译通过 ≠ 图标正确。** `aapt2` 把 `pathData` 当不透明字符串，
> **非法指令和越界坐标都能编译通过**。所以必须另跑几何校验（§4.2 ⑦），
> 有条件的话再在真机上 `PathParser` inflate 一次。

|---|---|---|---|
| 滚筒 | 提升筋旋转 0→360° | 3200ms · linear · 无限 | **订单状态 == 清洗中** |

**四个实现要点（易错）**

1. **滚筒只转提升筋**，外圈不参与 —— 外圈是正圆，转它看不出来还白费性能
2. **水滴的缩放圆心定在 `(12,14)`，不是 `(12,12)`** —— 定在中点的话上尖会左右甩
3. **水波两条线同相位** —— 错相位会看起来像两条不相干的线，不像水面
4. **泡沫三个一起动会像整体位移**，必须错峰（第二个延迟 700ms）

**Compose 实现骨架**

```kotlin
// 滚筒：只在订单真的在洗的时候转
@Composable
fun DrumIcon(state: OrderStatus, tint: Color) {
    val reduce = LocalReduceMotion.current          // §8
    val angle = remember { Animatable(0f) }
    LaunchedEffect(state, reduce) {
        if (state == OrderStatus.WASHING && !reduce) {
            angle.animateTo(360f, infiniteRepeatable(tween(3200, easing = LinearEasing)))
        } else {
            angle.stop()                            // 停下时停在当前角度，不回零
        }
    }
    Canvas(Modifier.size(26.dp)) {
        drawCircle(tint, style = Stroke(2.dp.toPx(), cap = StrokeCap.Round))   // 外圈，不转
        rotate(angle.value, pivot = center) {
            repeat(3) { i -> rotate(i * 120f) { drawLine(/* 提升筋 */) } }
        }
    }
}
```

**reduced motion**：四个全部停住，图形完整可读。停下来不丢信息——滚筒仍是一台机器，水滴仍是一滴水。
**红线**：订单没在「清洗中」，`DrumIcon` / `FoamIcon` 不许动。

## 7. 动效规范

**全局唯一 vocabulary**（`common/utils/AnimationUtils.kt`，禁止在页面里写魔法值）：

| 名称 | 参数 | 用途 |
|---|---|---|
| `defaultSpring()` | `spring(dampingRatio = 1f, stiffness = 350f)` | 卡片入场、选中态、所有非手势位移 |
| `momentumSpring()` | `spring(0.8f, 350f)` | **仅**带惯性的动作（掷币落定、爻坠落、甩环） |
| `heavySpring()` | `spring(0.8f, 200f)` | 大质量物体 |
| `pressTween()` | `tween(100ms, FastOutSlowIn)` | 按压反馈（配合 scale 0.97） |
| `CROSSFADE_ALT_MS` | `180ms` | reduced motion 降级专用 |

硬规则：
- 位移动画**禁止**用固定时长 `tween`，一律弹簧（从当前值动画，天然可中断）
- 按压反馈全应用强制：**scale 0.97**（不再出现 0.95 / 0.98）
- 列表逐项入场：间隔 ≤60ms，**总时长 ≤400ms**
- 页面转场用 NavHost 默认 + fade，不搞花哨转场

**红线：动画只能由真实状态触发。** 禁止伪造支付成功、订单完成、算法结果——没有真实事件就不放动画。

## 8. reduced motion（强制）

判定：`Settings.Global.ANIMATOR_DURATION_SCALE == 0`，经 `LocalReduceMotion` 在 Compose 树内共享。

**取消**：无限旋转、回弹、位移、缩放、逐项延迟、逐字动画。
**保留**：文字、颜色、图标、状态可读性；触觉保留（降级不是没有反馈）。

| 动效 | 降级后 |
|---|---|
| 按压缩放 | 改为轻微透明度变化 |
| 卡片/列表入场 | 纯 180ms 淡入，位移归零 |
| 骨架屏微光 | 静态浅灰块 |
| 滚筒圆旋转 | 静止在当前角度，盘面完整可读 |
| 摇卦动画 | 直接定格结果，保留落定触觉 |

新增任何动效**必须**同时给出 reduced motion 表现，否则不予合入。
