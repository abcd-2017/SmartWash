# games-library · 游戏正本目录规范

游戏正本统一 git 管理于此目录。**每个游戏一个子目录，结构固定为两个文件**，Web 管理后台上传游戏时可直接「选择游戏目录导入」，README 元数据会自动填充上传表单。

## 目录结构

```
games-library/
├── README.md          # 本规范
├── PROGRESS.md        # 主题化进度
├── GAME-THEME.md      # 主题规则与 token 映射
└── <game-key>/        # 目录名 = gameKey（小写字母开头，小写字母/数字/-/_）
    ├── index.html     # 游戏正本：单文件自包含 H5（CSS/JS 全内联，零外链）
    └── README.md      # 游戏文档：首行为机器可读元数据行（格式见下）
```

- 除 `index.html` 与 `README.md` 外不得有其他可见文件（`.DS_Store` 等隐藏文件忽略）；需要多文件的请自行打 `.zip` 走手动上传，单文件不超过 10MB。

## README 首行格式（自动填表数据源）

```markdown
# <中文标题>（gameKey：`<game-key>`，category 建议：`<category>`）
```

- **中文标题**：列表展示名，≤32 字。
- **gameKey**：与目录名一致；同 gameKey 重复上传视为覆盖更新。
- **category 建议**：只能取端上白名单 `puzzle / arcade / word / board / other`（对应 益智/街机/文字/桌版/其他，与 Android `GameCategory` 枚举对齐）；写了白名单外的值（如 rhythm/physics）上传时会回落为「其他」。

正文建议保留三行固定前缀（`- 玩法：` / `- 操作：` / `- 说明：`），其中**「玩法」行会被截取为上传表单的描述（≤128 字）**；「操作」「说明」仅供人读，不参与填表。其余内容（自查清单等）不限。

## 示例

```markdown
# 贪吃蛇（gameKey：`snake`，category 建议：`arcade`）

- 玩法：15×15 Canvas 网格，操控蛇吃红色食物……（≤128 字，上传时自动填入描述）
- 操作：触屏滑动手势转向，键盘方向键 / WASD……
- 说明：单文件自包含 H5……

## 自查清单

- [x] 无外部请求：CSS/JS 全内联，零 CDN / 字体 / 图片
```

## 新增游戏流程

1. 按 `snake/` 的样子建目录：写 `index.html`（过三关自查：JS 语法可解析 / 零外链 / 体积增幅 ≤30%）+ 按上述格式写 `README.md`。
2. Web 管理后台「游戏库 → 上传游戏 → 选择游戏目录导入」，核对自动填好的表单（图标/色组/角标/排序仍需人工选），确认上传。
3. 在列表中打开「下发」开关，App 游戏中心即会展示。
